# PW1 0.3.5 — automated lifecycle checks

Date: 2026-10-15. These are the pre-release automated checks. A subsequent
physical run confirmed power save-and-exit and successful launcher notification,
but the user reported reopening failed. See the separately preserved
[device log](pw1-0.3.5-power-ui.txt) and [0.3.6 follow-up](pw1-0.3.6-checks.md).

## Verified locally

- `python3 scripts/kindle/check-host.py`: complete host suite passed, including backend, display, power/system commands, session, launcher, TXT UI and native HAL/worker checks.
- `python3 platform/kindle/check-launcher.py`: final runner passed 35 scenarios. These include native production notifier → real runner → forced cleanup, power and corner requests, controlled setup/Restore contention, failed STOP/bar journals, failed bar restoration/redraw with retry, and delayed cleanup with a stale token.
- `check-session.py`: production owner validation passed with an intermediary, absent PID environment, stale boot/start, invalid PID and replacement-owner rejection; kernel guard contention, bounded cleanup retry and lock-owner SIGKILL passed.
- `DisplayChecks`: normal restoration, write-free post-join handoff, draining a blocked publication and cancelling pending publication passed. The separately painted stock frame survived cleanup/destruction.
- `check-power.py`: event fragmentation, overflow, failure/restart, helper parent death, bounded state/Pillow commands, active-only Home redraw, sleep skip, failed/unknown queries and failed/timed-out redraw passed.
- ARM session, display and power/system checks passed under qemu-arm-static with the kindle5 glibc 2.12.2 sysroot available (`-L`). Session checks use isolated proc identities because the execution host exposes a different PID namespace; production uses `/proc`.
- ARM TXT checks passed with identical ARM/host preview pixels.
- Static ARM softfp/Linux 2.6.31 ELF and expanded NSS symbol audits passed. clang-format 21 and `git diff --check` passed. SDK remains pinned at `699370183fa3a0e33c9cb83a36f701bbb6022095`.

## Scope and limits

The race tests control scheduling with barriers and mock stock processes/UI;
they prove the bad interleaving is excluded, not a device failure probability.
The publication test cannot cancel an ioctl already submitted to the kernel.
The kernel lock is independent of the launcher's persisted session directory;
its permanent inode must not be unlinked while any operation runs.

The five-minute session and six-minute watchdog remain. Retest power → wake →
reopen/progress, normal Exit, corner hold and the session timeout on the PW1.
Observe the status bar during reading and the sleep image. Confirm
`launcher_identity ... valid=1`, `launcher_signal=12 sent=1` and
`power_handoff=launcher grace_seconds=2` for power, or signal 10 for corner hold.
The successful 0.3.4 device log remains separate historical evidence.
