# PW1 0.3.6 — reopening and inherited-descriptor checks

Date: 2026-10-15. Physical validation of 0.3.6 is pending.

## Device evidence versus local reproduction

The [0.3.5 device log](pw1-0.3.5-power-ui.txt) confirms successful startup,
an intermediary `sh`, native launcher notification, page 2 saved, power exit,
volumd/bar restoration and stock screenSaver state. The user reported reopening
failed and launcher.log was empty. Neither attachment records that failed
attempt. Its exact cause is therefore unknown.

Using the 0.3.5 production stock-command implementation locally, a mock command
forked a descendant which closed stdio but inherited the operation flock. The
direct helper and native cleanup phase returned 0; a subsequent guard returned
75 until the descendant exited. This establishes a defect in descriptor
handling, not the physical failure's cause.

## Automated checks

- `python3 scripts/kindle/check-host.py`: complete host suite passed, including
  backends, concurrent display, power/system, session, descriptors, 43 launcher
  cases, TXT UI and native HAL/worker checks.
- Launcher additions exercise native reader registration and notification
  through an intermediary shell, reopen after power exit, stale-session reopen,
  helper-descendant descriptor retention, and reopen overlapping cleanup.
  Existing journal/race, stale-token, bar/repaint failures and retry checks pass.
- `check-session.py`: owner validation, contention, owner death and explicit
  inherited unlock pass. A delayed unlock through the old open-file description
  leaves a replacement owner's lock intact. This last regression was added after
  the full host run and rerun separately on host and ARM.
- `check-descriptors.py`: both query and subscriber helpers spawn a live
  descendant. No inherited guard inode, including duplicate fd 8, reaches it;
  another launch can acquire the guard while the descendant remains alive.
- Static ARM power/system, session and descriptor checks pass under
  qemu-arm-static with the kindle5 glibc 2.12.2 sysroot available (`-L`). Session
  fixtures use isolated proc identities because the execution host exposes a
  different PID namespace; production uses `/proc`.
- ARM TXT checks pass with identical ARM/host preview pixels. ELF is static
  ARM softfp, minimum Linux ABI 2.6.31; the pre-strip NSS audit passes.
- clang-format 21, shell syntax, Python compilation and source whitespace checks
  pass (`git diff --cached --check` excludes the byte-preserved device log,
  whose two raw power-event lines contain trailing spaces).
  The SDK remains pinned at `699370183fa3a0e33c9cb83a36f701bbb6022095`.

## Limits and physical retest

Mocks control scheduling; no device failure probability can be inferred. The
uploaded PW1 BusyBox 1.17.1 shell could not execute in the available emulator
(failed before its first syscall); the observed intermediary relationship is
covered by a controlled wrapper, not a claim of exact old-ash emulation.

After installing over 0.3.5, restart once to discard descriptors retained by
pre-update processes. Preserve data and the permanent operation.lock inode.
Repeat open → page turn → power sleep → wake → KUAL reopen and verify progress.
Then check normal Exit, corner hold, timeout and visual bar/sleep behavior.
Collect launcher.log, ui.log and ui.previous.log even if opening fails.

Five-minute sessions, the six-minute watchdog, save-and-exit power policy and
TXT-only support remain. In-memory suspend/resume and EPUB are not implemented.
